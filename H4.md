> ## b) APDU  
> **APDU** (application protocol data unit) is the communication unit used for interaction between
> a card reader and a smart card.
> 1. **Command APDU structure**    
> When a reader sends a command to the card, it always consists of a mandatory header and an
> optional body.
> - Header (4 bytes), mandatory
>    - CLA (class): indicates the message class
>    - INS (instruction): the actual command, what should card do
>    - P1 & P2 (parameters): additional instructions for the command
> - Body, optional
>   - LC (length of command data): indicates the number of bytes of data that follow
>   - Data: the actual information being sent
>   - LE (length of expected data): tells the card the maximum number of bytes the reader
>     expects to receive in response
> 
> 2. **Response APDU structure**   
> The card's response to the reader is usually shorter. It contains:
> - Response data: included only if the reader requested information
> - Status words (SW1, SW2): These are mandatory. They indicate the outcome of the command
